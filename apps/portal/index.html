一个闭环，七步都留证据。

01

采集证据

Playwright 双视口截图，HTTP、DOM、溢出与错误遮罩检查。证据带 ID，可追溯。

02

盘点设计基础

token、组件、模式先记为「已观察」；人批准的才是规则。

03

诊断排序

impact × confidence ÷ effort；人可以推翻，必须留理由。

04

隔离执行

选定的 agent 在独立 worktree 里改，不 push、不部署。

05

前后评估

同样的状态重新渲染，结构检查逐项对照。

06

独立 Visual QA

截图复核单独作证；没通过，不接受。

07

人的判定

accept / reject 带理由，写入不可变的 run 账本。

Get Started，一条命令五分钟。

01

接入并采基线——校验 checkout、起预览、等页面就绪、建 run、双视口截图。

bash
pnpm harness onboard --config examples/happyclaw-site/project.json
02

看完基线截图，确认一条 finding，剩下的交给闭环。

bash
pnpm harness confirm --run … --finding F1 --verdict supported
pnpm harness plan    --run … --finding F1
pnpm harness execute --run … --repo ../your-app --agent codex

Node 22.15+ / pnpm 11.19+ · 仓库：github.com/ShuaiMXu/creative-os

用你的 agent跑一遍。

两个适配器，同一条权限边界：独立 worktree，不 push、不 merge、不部署，宿主仓库指纹前后核验。

codex exec 
codex exec -C <worktree> -s workspace-write --json -o agent-last-message.md -

Prompt 走 stdin；仓库文件一律当作数据，不当作指令。
