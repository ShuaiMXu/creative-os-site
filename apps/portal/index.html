用你的 agent跑一遍。

两个适配器，同一条权限边界：独立 worktree，不 push、不 merge、不部署，宿主仓库指纹前后核验——被动过，该次 run 即判失败。

codex exec 
codex exec -C <worktree> -s workspace-write --json -o agent-last-message.md -

Prompt 走 stdin；仓库文件一律当作数据，不当作指令。

适配器注册表：packages/harness-core/agents.js · 说不清如何满足边界的适配器不会被加载

一条命令，五分钟接入。

01

接入并采基线——校验 checkout、起预览、等页面就绪、建 run、双视口截图。

bash
pnpm harness onboard --config examples/happyclaw-site/project.json
02

看完基线截图，确认一条 finding，剩下的交给闭环。

bash
pnpm harness confirm --run … --finding F1 --verdict supported
pnpm harness plan    --run … --finding F1
pnpm harness execute --run … --repo ../your-app --agent codex

Node 22.15+ / pnpm 11.19+ · 换应用就复制一份 project.json 改四个字段

能用什么，没什么，写在一处。

已可用

  • — Experience Spec 校验，证据 ID 可追溯
  • — 双视口浏览器采集与结构检查
  • — 27 个带版本 Skill，处理器白名单
  • — 隔离执行 + 宿主仓库指纹核验
  • — 前后评估、独立 Visual QA、人的判定
  • — 不可变的 run 账本与导出

仍在开发

  • — 看截图的视觉判断（当前一律 needs-evidence）
  • — Experience Score 校准与发布
  • — 增量审阅与 Git diff 影响映射
  • — 多步任务采集与状态重放
  • — Workbench 的写入操作（现仅 CLI）

失败的 run 和缺失的证据保持可见，不会被替换成示例性的成功。

现在，从一个真实的应用开始。
